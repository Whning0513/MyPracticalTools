# 从会话存档提炼的可复用工具清单

[English](session-derived-tool-backlog.md) | [简体中文](session-derived-tool-backlog.zh-CN.md)

这份清单来自四份可读取 Codex 存档的聚合分析：当前工作站存档、转换后的历史存档、一份便携备份和一份计算节点存档。它们共包含 6,294 个会话文件、464,350 条 JSONL 记录，时间覆盖 2026 年 6 月至 9 月。

分析过程只保留计数、日期、任务类别和工具名称，没有保留或发布提示词、回复、命令参数、工具输出、工作目录、主机名、账号名和凭据。转换后的历史存档使用精简格式，因此只计入存档数量，不参与任务类别排序。

## 下一批候选

1. **产物清单生成与校验器。** 生成包含相对路径、字节数、哈希、媒体类型和可选数据切分标签的确定性清单，并在传输后校验。数据与产物工作在计算节点存档中出现于 107 个会话，在工作站存档中出现于 51 个会话。
2. **远程任务交接快照。** 用一个脱敏 JSON 文件记录任务名称、状态、检查点、日志位置、GPU 分配和重启说明。远程计算和实验运行是计算节点存档中最常见的两类工作。
3. **脱敏的 Codex 配置备份与对比。** 只导出白名单内的配置、skills 和指令文件，同时拒绝 token、历史记录、缓存、机器绝对路径和身份文件。环境与配置工作在工作站存档中出现于 67 个会话。
4. **只读贡献队列快照。** 针对明确的仓库白名单，汇总 review、CI、维护者请求和停滞时间。GitHub 贡献工作在工作站存档中出现于 59 个会话。工具不得发送评论、关闭、合并或修改任何内容。

前两个候选最容易跨机器复用。配置备份有实际价值，但必须使用足够小的白名单。贡献队列应保持只读，避免一次整理演变为批量账号操作。

## 进入仓库的标准

候选工具需要有明确的输入格式、不包含私密正文的输出、至少一条完整使用命令、覆盖失败路径的测试，并且能服务于不止一个已归档任务，才适合加入本仓库。
